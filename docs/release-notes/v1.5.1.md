## v1.5.1

### バグ修正
- **マルチモニタ + マルチ DPI 環境でジャンプ位置が大きくずれる不具合への追加対策 (バグ1 続)**: v1.5.0 で導入した `SendInput(MOUSEEVENTF_VIRTUALDESK)` 経路は、Dynabook 内蔵 (150% DPI) + 外部モニタ (100% DPI) の混在構成では効かないことが実機ログで判明。新たに以下 2 段の対策を実装:
  - **モニタ別相対座標方式**: 保存座標に「所属モニタの DeviceName + そのモニタ内の相対オフセット」を併記。再生時はモニタの現在 Bounds から絶対座標を再計算する。これにより OS の DPI 仮想化による物理絶対座標の誤解釈を根本回避。
  - **`SetThreadDpiAwarenessContext` でカーソル設置 API のコンテキスト明示**: 既定の経路を `SetCursorPos` 直前にスレッド DPI コンテキストを `PER_MONITOR_AWARE_V2` で設定するパスに変更 (`JumpStrategy.DpiContext`)。Win11 + マルチ DPI 環境で OS 内部の DPI 仮想化キャッシュが期待通りの位置にカーソルを置けるよう促す。
- **旧 settings.json の自動マイグレーション**: 既存ユーザーの座標データに対して、起動時に `MonitorRelativeX/Y` を自動補完して書き戻す。手動操作不要。

### 機能追加
- 詳細ログモードの出力を強化: ジャンプ前ログに「`rel=(MonitorRelativeX,Y)` `jump=(計算後絶対座標)` `source=monitor-relative or absolute-fallback`」を追加。ジャンプ位置決定の経路が即座にわかる。

### 内部変更
- `AppSettings.JumpStrategy` enum (`DpiContext` / `SendInputVirtualDesk` / `LegacySetCursorPos`) を導入。既定は `DpiContext`。旧 `UseSendInputForJump` フィールドは後方互換のため保持されるが効果なし。
- `SavedCoordinate` に `MonitorRelativeX` / `MonitorRelativeY` プロパティを追加 (デフォルト -1 = 未設定)。
- `CoordinateStore.Load` がマイグレーション発生時に `true` を返し、`MainWindow` が即座に `Save` する。
- ユニットテストにマイグレーション動作のケースを追加 (合計 10 ケース)。
